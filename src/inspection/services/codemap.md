# src/inspection/services/

## Responsibility

Service implementations backing the inspection HTTP routes (and tests). Four classes — `JobsListService`, `JobsShowService`, `RunsListService`, `RunsShowService` — translate user-facing identifiers and refinements into repository queries, map raw rows into the typed inspection envelopes (`JobListResult`, `JobShowPayload`, `RunListRow`, `RunShowPayload`), and surface inspection-typed errors (`InspectionValidationError`, `InspectionNotFoundError`, `InspectionResourceNotFoundError`). This folder is the only module under `src/inspection/` permitted to import `src/persistence/repositories/`.

## Design

Thin service layer over `src/persistence/repositories/`. Each class is constructor-injected with `Repositories` and exposes a single read-only entry point (`list`, `show`). The services own validation (`JobsListService.validateInput`, `RunsListService.resolveLimit`), identifier resolution (`resolveJobIdentifier`, `parsePrefixedId` from `src/persistence/identifiers.ts`), cross-table in-memory joins (active filter/score lookup helpers `findActiveFilter`/`findActiveSuccessfulScore`/`findActiveFailedScore`/`scoreStatusFor`, `computeJobCounts`, `computeFilterCounts`), and row→variant mapping (`mapJobRowToListRow` plus per-state mappers `jobRowToAllRow`/`ScoredRow`/`AcceptedRow`/`RejectedRow`/`UnscoredRow`/`PartialRow`/`FilterErrorsRow`/`ScoringErrorsRow`, `discoveryErrorToFailedRow`, `rowToListRow`, `searchExecutionToListRow`). Pure helpers — `sortJobListRows`, `summariseSearchErrors`, `linkedinJobUrl`, `parseSearchErrors`, `scoreCategoryScores`, `rejectionReasonsAsStrings`, `latestFailedAttempt` — keep the SQL in the repository and the projection here. The `failed` state in `JobsListService` is a special branch that sources from `JobRepository.listDiscoveryErrorsByRun` instead of `listByState`, and `RunsShowService.show` derives `jobCounts` by joining `discoveryEvents` to `JobRow.extractionStatus` via per-id `findById` lookups. Service inputs are `JobsListInput` / `RunsListInput`; option bags are `JobsListServiceOptions` / `JobsShowServiceOptions` / `RunsListServiceOptions` / `RunsShowServiceOptions`.

## Flow

`JobsListService.list(input)` → `validateInput` (throws `InspectionValidationError` on bad `limit`/`minScore`/`runId`) → branch on `'failed'` (`fetchFailedRows` → `jobs.listDiscoveryErrorsByRun` + `pipelineRuns.findSearchById`) or eight job-shaped states (`jobs.listByState`) → `mapJobRowToListRow` per row → `sortJobListRows` (stable sort, `sourceJobId` tie-break) → `slice(limit)` → `JobListResult` envelope.
`JobsShowService.show(identifier)` → `resolveJobIdentifier` (translated to `InspectionNotFoundError('jobs_show_invalid_identifier')` on failure) → `jobs.findById` with `jobs.findBySourceJobId` fallback → parallel fetch of discovery events, filter results, score results, extraction attempts → pick latest active rows → assemble `JobShowPayload` (drops the `evidence` sub-array from `categoryScores`).
`RunsListService.list(opts)` → `resolveLimit` (default `DEFAULT_RUNS_LIST_LIMIT = 20`) → `pipelineRuns.listRecent(limit)` → `rowToListRow` (synthesises `errorSummary` via `summariseSearchErrors`, returning `'none'` or `<code>: <count>`) → `readonly RunListRow[]`.
`RunsShowService.show(identifier)` → `parsePrefixedId(identifier, 'run')` → `pipelineRuns.findWithDetails` → parallel fetch of active scores, diagnostics, filter results, discovery events → `computeJobCounts` + `computeFilterCounts` + denormalised `scoreCounts` (uses `row.scoresReused`, `row.scoringErrors`) → `RunShowPayload` with `searchExecutions` projected via `searchExecutionToListRow`.

## Integration

Called from `src/inspection/` route handlers and formatters. The service instances are constructed once per sidecar request, wired with the shared `Repositories` container and (where needed) `formatDisplayScore` from `src/scoring/score-formula.js`. Returned envelopes (`JobListResult`, `JobShowPayload`, `RunListRow`, `RunShowPayload`) feed the table/JSON renderers; thrown errors map to the corresponding HTTP status responses by the sidecar's error mapper (validation: 400; not-found: 404). Side effects are read-only — no Playwright, OpenAI, `drizzle-orm`, or Pino imports in any file.
