# src/profile/openai/

## Responsibility

OpenAI client wrapper purpose-built for profile extraction: structured outputs, prompt templates, retry policy, and a deterministic fake client for tests. This module isolates every interaction with the `openai` SDK so the rest of the codebase depends only on the narrow `OpenAIClient` interface. It also serves the job-scoring pipeline via the same client surface (`ScoringStructuredOutput` registered alongside `ExtractedProfile`).

## Design

- **SDK boundary.** `client.ts` is the only module that imports `openai` and `openai/error`; `createDefaultOpenAIClient` returns an object satisfying `OpenAIClient` (`extract(request): Promise<OpenAIExtractionRawResponse>`). Every other module — domain code, tests, retry, errors — depends on the interface in `types.ts`.
- **Adapter + registry.** The `OpenAIExtractionRequest` carries `responseSchemaName` and `structuredOutputSchemaVersion`; `response-schemas.ts` maps those to a JSON Schema via `getResponseSchema(name, version)` over the `Readonly` `RESPONSE_SCHEMA_REGISTRY`. Adding an operation is a registry entry — no client changes.
- **Structured output.** `structured-output.ts` defines the Zod source of truth (`ExtractedProfileSchema`, sub-schemas, `STRUCTURED_OUTPUT_SCHEMA_VERSION = 1`) and `createExtractedProfileSchema(knownSourceIds)` which `superRefine`s every `SourceReference.sourceId` against the request's source set. `prompt.ts` projects the Zod schema to JSON Schema and applies OpenAI strict-mode adjustments: `ExtractedSkill.category` and `ExtractedLanguage.level` are widened to `['string', 'null']` and pushed into `required`, with `null` appended to their enums so the model can signal "unknown" without inventing a value.
- **Prompt builder.** `buildProfileExtractionPrompt({ promptVersion, sources })` returns `{ systemMessage, userMessage }`; the system message enforces JSON-only output, no invented facts, source-attributed citations, and date formatting. `userMessage` embeds a source manifest + each source's text delimited by `--- sourceId: source_<n> (<filename>) ---` banners. Prompt version is pinned to `PROFILE_EXTRACTION_PROMPT_VERSION` in `fingerprint.ts` and validated at call time.
- **Error taxonomy.** `errors.ts` defines `ProfileExtractionError` (exit code `ExitCode.OpenAIFailure`) with retryable (`OpenAIRateLimitError`, `OpenAIServerError`, `OpenAITimeoutError`, `OpenAINetworkError`, `OpenAIInvalidOutputError` — all carrying `retryAfterMs`) and non-retryable (`OpenAIAuthenticationError`, `OpenAIPermissionError`, `OpenAIBillingError`, `OpenAIInvalidRequestError`, `OpenAIUnsupportedModelError`, `ProfileExtractionInputTooLargeError`, `ProfileExtractionSourceUnusableError`) subclasses. `OPENAI_RETRYABLE_ERROR_CODES` is the `ReadonlySet<string>` the retry policy uses for code-based classification (no `instanceof`). `client.ts::translateSdkError` maps `AuthenticationError`/`PermissionDeniedError`/`RateLimitError`/`BadRequestError`/`NotFoundError`/`APIConnectionTimeoutError`/`APIConnectionError`/`InternalServerError` into the typed family; on 429 it inspects `QUOTA_ERROR_CODES` (`insufficient_quota`, `billing_not_active`, `billing_hard_limit_reached`, `account_deactivated`, `plan_upgrade_required`) and maps to `OpenAIBillingError` rather than burning the retry budget on a permanent billing failure. A duck-typed fallback (`translateByStatus`) covers synthetic errors.
- **Retry policy.** `runWithRetry(operation, RetryOptions)` in `retry.ts` applies exponential backoff with full jitter (defaults: `maxAttempts: 3`, `baseDelayMs: 500`, `maxDelayMs: 8_000`, `jitter: 'full'`). `Retry-After` headers are honored once and clamped to `[0, maxDelayMs]`. `OpenAIInvalidOutputError` is special: it gets a single corrective retry — a second invalid output aborts. `sleep` and `now` are injectable for deterministic tests; a seeded LCG PRNG makes jittered delays reproducible when `now` is fixed. On final failure, the `attempts` array is attached to the thrown `ProfileExtractionError` for persistence.
- **Fingerprint.** `calculateExtractionFingerprint` in `fingerprint.ts` returns a SHA-256 hex digest over a stable JSON serialization of sorted source hashes + `schemaVersion` + `promptVersion` + `model` + `reasoningEffort` + `structuredOutputSchemaVersion` + `extractorImplementationVersion` (default `'1.0.0'`).
- **Fake client.** `FakeOpenAIClient` in `fake-client.ts` implements `OpenAIClient` with a queue of `FakeOpenAIClientScript` entries (responses, error, delayMs). Requests are recorded in `.requests`. Past exhaustion, it falls back to the last script so retry loops past the queue still get deterministic values.

## Flow

1. **Build request.** Caller (`ProfileExtractionService`) constructs an `OpenAIExtractionRequest`: assembles `messages` via `buildProfileExtractionPrompt`, sets `responseSchemaName: 'ExtractedProfile'` and `structuredOutputSchemaVersion: STRUCTURED_OUTPUT_SCHEMA_VERSION`.
2. **Execute with retry.** Wraps `client.extract(request)` in `runWithRetry(..., RetryOptions)`. Each iteration records an `AttemptRecord` (`{ attemptNumber, succeeded, errorCode, errorMessage, retryAfterMs }`).
3. **Transport.** `createDefaultOpenAIClient` returns an `OpenAIClient`; on `extract`, it calls `getResponseSchema(name, version)`, issues `sdk.chat.completions.create` with `response_format: { type: 'json_schema', json_schema: { name, schema, strict: true } }`, and returns `{ rawJsonText, tokenUsage }`. SDK errors flow through `translateSdkError` to typed `ProfileExtractionError` subclasses.
4. **Backoff.** On retryable codes (`OPENAI_RETRYABLE_ERROR_CODES`), `computeDelay` returns either the clamped `retryAfterMs` or `rng(0, min(maxDelay, base * 2^(attempt-1)))`.
5. **Validate.** Caller parses `rawJsonText` with `createExtractedProfileSchema(knownSourceIds).safeParse(...)`; `superRefine` rejects unknown `sourceId` references. A validation failure throws `OpenAIInvalidOutputError`, which gets one corrective retry.
6. **Fingerprint + persist.** Caller computes `calculateExtractionFingerprint({ sourceHashes, schemaVersion, promptVersion, model, reasoningEffort, structuredOutputSchemaVersion })` and writes an `openai_request_metadata` audit row.

## Integration

- **`src/profile/extraction-service.ts`** — primary consumer; imports `errors`, `fingerprint`, `retry`, `prompt`, `structured-output`, and `types`; orchestrates the request/validate/persist flow described above.
- **`src/profile/post-process.ts`** — imports `ExtractedProfileSchema` for post-extraction normalization (defaults for `category`, `level`).
- **`src/profile/conflicts.ts`** — imports `ExtractedProfileSchema` to detect cross-source conflicts.
- **`src/profile/schema.ts`** — re-exports primitives (`LanguageLevelSchema`, `SkillCategorySchema`, etc.) the OpenAI structured output builds on.
- **`src/profile/editing/`** and **`src/profile/review/`** — downstream services consume the persisted `ExtractedProfile` produced by this module; the structured-output types and errors are re-exported through `src/profile/index.ts` (`export * from './openai/index.js'`).
- **Tests** — `FakeOpenAIClient` + injectable `sleep`/`now` in `RetryOptions` enable deterministic tests of the full extract/retry/validate pipeline without network calls.
